# 模拟文档 + 真机演练：练习计划（2026-11-10）

模拟文档：[5D 并行规划与通信时间线](https://claude.ai/artifact/DMDryAR9ePkAnmVowTTo7z)。真机：本 kit 的快速路径（`PLAYBOOK.md` 第 0 节），K3 缩小版，16 / 32 / 64 卡。

**做法：** 每一档卡数都按"先预测、再跑、再对表、再校准"做一遍。下一档只用上一档校准过的参数去预测，预测误差就是这个模拟器可不可信的度量。三档都对上以后，再用它外推全尺寸 K3，这才是模拟文档原本的用途。

## 0. 前置：让模拟文档能表达真机的格子（一次性，本机）

| 缺什么 | 真机是什么 | 要在模拟文档里加的 | 状态 |
|---|---|---|---|
| 模型 | `k3_16x80g`、`k3_32x80g`、`k3_64x80g`、`_e256`、`_e512`（D 2304，29 / 61 / 93 层，128 / 256 / 512 个专家，top-16） | K3 缩小版这几个模型 | 未做 |
| 卡数 | 16、32、64 | 卡数选项里加 16、32、64（现在最少 128） | 未做 |
| EP 实现 | titan 默认的 NCCL all-to-all，不重叠 | 除 DeepEP、MoonEP 外，加一个"NCCL all-to-all" | 未做 |
| 效率假设 | eager（`MN_COMPILE=0`），kernel 没调优 | GEMM、注意力、线性注意力、NVLink / IB 集合和 all-to-all 的效率改成可编辑（现在只能看，校准要改它们） | 未做 |

## 1. 两边的设置怎么对应

| 真机 | 模拟文档 |
|---|---|
| `MN_CELL` 的 pp、dp、cp、tp、ep | PP、dp_shard、CP、TP、EP；dp_replicate 填 1 |
| `MN_VPP`（快速路径 2，部分行 4） | VPP |
| 序列 16384（OOM 时减半） | 序列长度；全局 batch = 524288 ÷ 序列（16K 时 32 条），MBS 1 |
| `Interleaved1F1B` | PP 调度 Interleaved 1F1B |
| CP `allgather` | softmax 层的 CP 算法 AllGather KV |
| 有 PP 的格子；`MN_FSDP_KEEP=1`；其余 | FSDP 整步不 reshard（PP > 1 时自动）；整步不 reshard；逐层 reshard |
| titan 默认 remat（只重算路由专家的 w13） | 激活重计算"选择性"（最接近，不完全相同） |
| AdamW，fp32 主参数，bf16 计算 | 优化器 AdamW，GEMM 精度 BF16 |
| H100，IB 实测每口约 46 GB/s，跨节点 sendrecv 43 GB/s | H100 · NVL8；集群参数里 IB 带宽改成实测值 |

## 2. 对表：比哪些量

| 量 | 真机从哪读 | 模拟文档哪里看 |
|---|---|---|
| 步时间 | `summary.tsv` 的 `step_s_clean`（去掉第 1 步和录 trace 的那一步再取中位数） | 结果里的步时间 |
| MFU、峰值显存 | `measure_summary.tsv` | 结果里的 MFU、显存 |
| 计算、暴露通信、空闲的占比 | `measure_trace_report.tsv`（录 trace 的那一步） | step 账本 |
| 每个维度的暴露（PP、EP、TP、CP、FSDP） | `measure_trace_report_pg.tsv` 按标签加总 | step 账本里每个维度的等待 |

对之前先做三件事：
- **查慢卡：** 看 `gpu_by_cell.tsv` 或监控的降频列。模拟器假设每张卡一样快，有降频卡的格子只比方向，不拿来校准（11-08 的 rank 13 就是这种）。
- **只比同类的量：** trace 里 NCCL kernel 的时间含等对方的时间，要和模拟文档里同样含等待的那一项比。
- **分清两种时间：** 录 trace 的那一步比前几步慢 5% 到 30%，步时间不拿它比，只用它的占比。

## 3. 校准规则

- 同一档卡数用一组参数解释所有格子，不逐格调。
- 只调效率和带宽（GEMM、注意力、线性注意力、集合通信和 all-to-all 的效率，MoE 负载不均，IB 带宽），不改模型结构和 mesh。
- 参数每改一次就记一个版本（v0、v1、……），写清楚改了什么、根据哪一格。
- 合格线：
  - 步时间误差在 20% 以内；
  - 几种布局谁快谁慢的排序一致；
  - 每格暴露最多的维度一致。

## 4. 练习顺序

| 轮 | 在哪 | 做什么 | 产出 | 花费（纸面） |
|---|---|---|---|---|
| 0 | 本机 | 补模拟文档（第 0 节）。用 11-08 的 `k3_A`、`k3_B`、`k3_C`、`k3_D` 做第一次对表；有慢卡，只定一个草稿版参数 | 参数 v0 | 0 |
| 1 | 16 卡 | 干净重测：筛查过关后跑整个矩阵（含重复行和 compile 行）。先用 v0 预测各行，写进 `PREDICT.tsv` 并提交，再跑；对表，定 v1；填结果 README 的 MFU 差距拆分表 | v1，16 卡误差表，噪声底线 | 约 $50 到 60 |
| 2 | 32 卡（可选） | `apply 4 +core`：只用 v1 预测，先提交预测再跑；算误差；再定 v2 | v2，32 卡误差表 | 约 $70 |
| 3 | 64 卡 | `apply 8 +core`，7 行约 50 分钟：用最新的参数预测，先提交再跑；算误差，这一轮是真正的检验 | v3，64 卡误差表 | 约 $130，从零 setup 再加 $30 到 40 |
| 4 | 本机 | 用 v3 在模拟文档里给全尺寸 K3（128 卡以上）出推荐配置，写明哪些参数是实测校准的、误差多大 | 外推结论 | 0 |

不做 128 卡：相对 64 卡新学到的东西很少。可靠性的部分不跑长 run，在 16 卡上做一次短演练（`PLAYBOOK.md` 第 8.2 节）。

每一档至少一对重复（`k3_A_rep`、`k3_A4_rep`、`k3_A8_rep`），成对对照表里的噪声底线就是它。

每一轮重点回答一个问题：
- **16 卡：** pp2 下 PP 暴露的 25% 里，多少是气泡和传输（模拟器能算的），多少是慢卡和等待（模拟器算不出的）。
- **32 卡：** PP 从 2 到 4 的代价是否按 (pp−1)/(v·m) 涨；61 层在 16K 会不会 OOM，模拟器的显存估计准不准。
- **64 卡：**
  - 93 层 pp8·v4 的气泡，以及 AttnRes 跨 stage 的数据量；
  - EP 16 跨节点比 EP 8 慢多少；
  - CP 跨节点的长上下文行。

## 5. 记在哪

- 每轮的结果目录是 `results/<日期>_<hw>[_n4|_n8]/`，在里面放 `PREDICT.tsv`，跑之前写好并提交，这样预测不会在看到结果后被改。它的列：
  - 预测：`row`、`sim_step_s`、`sim_mfu`、`sim_peak_gib`、`sim_top_exposed`、`params`（参数版本）；
  - 实测：`meas_step_s`、`meas_mfu`、`meas_peak_gib`、`meas_top_exposed`；
  - 误差：`err_step_pct`。
- 跑完补上实测列和误差列。这一轮校准后的参数版本写进那个目录的 `README.md`。
