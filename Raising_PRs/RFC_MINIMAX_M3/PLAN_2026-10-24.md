# MiniMax M3 进 torchtitan 的计划（2026-10-24）

依据：`RESEARCH_2026-10-24.md`（事实和来源）、`HF_SPEC_minimax_m3_vl_2026-10-24.md`（HF 实现规格，数值参考）、`LESSONS_4025_MAINTAINER_REVIEW.md`（#4025 维护者评审清单）。titan 侧的组件对应由子 agent 在 upstream main `3ed5aa97` 上只读整理，下面每条都写了 `path:line`；标"已核对"的是我亲自读过源码的。

## 0. 原则

- **HF 只当数值参考，不当代码模板**（tianyu-l 在 #4025："if we use slow HF implementation without torchtitan components during numerical verification; we'd have to do it again when swapping to titan modules"）。数值对齐在用 titan 组件写好的实现上做。
- **先定放置，再写代码**（CLAUDE.md "#4577 is the reference"）：每个组件先找到 titan 里负责它的类，能复用就复用，能加 Config 字段就加；新写的 private `def` 要在 diff 审计里写明搜过什么。
- **第一个 PR 就是占位**：eager 加 FSDP2，尽快开出来。K3 的教训是 #4025 在发布后 3 天就被别人开了。5D 的每个维度单独发 PR，不在本地攒。
- RFC 只是本地短稿（`RFC_DRAFT_2026-10-24.md`），tracking list 由维护者来开。

## 1. PR 拆分

- **common 的预备改动**：每个都很小、可以单独合入，对现有模型逐位不变。
  - P1：`OffsetRMSNorm` 从 `qwen3_5/model.py:73-96` 原样移到 `common/norm.py`，qwen3_5/6/8 只改 import。已核对：它就是 HF 的 Gemma 数值（fp32 下 `(1 + w) * norm(x)` 再转回）。
  - P2：部分 RoPE 移进 common，给 `GQAttention.Config` 加 `rotary_dim`（`common/attention/attention.py:192-292`，`make_gqa_config` 在 `config_utils.py:227-298` 同步加参数），`Qwen35Attention._partial_rope`（`qwen3_5/model.py:196-217`）改用它。已核对：那段代码上面的 TODO 就是 "consider moving this to rope directly"。
  - P3（视情况）：`make_ffn_config` / `make_shared_expert_ffn_config` / `make_routed_experts_config`（`config_utils.py:301-505`）加 `activation_fn` 参数。gpt_oss 目前是在自己的 flavors 里构造 `ClampedSwiGLU`（`gpt_oss/flavors.py:169-207`），实现时先看能不能照它的写法，不行再改 factory。
    - 【2026-10-24 订正】不需要改 factory：M3 照 gpt_oss 用 `dataclasses.replace(..., activation_fn=ClampedSwiGLU.Config())`。实际的 P3 变成了 DSV3 adapter 的两个 seam（`_build_from_hf_map`、`hf_rope_config_cls`，提交 `69dda371`）；另加 P1b（norm 类型放宽）、P4 / P5（5D 分支的两个 sharding config 进 common）。
- **M3 的第一个 PR**：模型加 FSDP2，范围见第 2 到 6 节。
- **后续，每个一个 PR**：TP 加 SP、EP、CP（MSA 的 CP 要单独设计）、PP、发布权重的导入（M3-MXFP8、M3.1-Flash 的 NVFP4）、indexer warmup 阶段（如果不进第一期）。

## 3. MSA 的写法

- **Indexer**（每个 MSA 层一个）：
  - `q_proj` 输出 4 个 index 头，每头 128 维；`k_proj` 输出 1 个共享的 key 头；q 和 k 都过 `OffsetRMSNorm`(128)，再用主注意力的同一份 RoPE 旋转前 64 维；
  - 输入是 detach 过的 hidden states（论文式 11）；
  - 选块：fp32 点积（为了和 HF 一致，选块时不除以 `sqrt(d)`，对 top-k 没影响），按因果和同一文档做 mask，128 个 token 一块取 max，自己所在的块设为 +inf，取 top-16（自己的块占一个名额），无效位置填 -1；
  - 按 query 块分段计算，控制显存。
- **稀疏注意力**：FlexAttention。
  - 每个 query 块的 BlockMask 取该块里所有 query 选中块的并集，再用 `mask_mod` 精确到 token 级（是否被这个 token 选中、是否因果、是否同一文档）；
  - 每个 KV 组的选择扩展到它的 16 个 query 头；
  - 输出 LSE，给 KL 的老师用。
- **KL loss**（论文式 9、10）：
  - 老师：组内 16 个头主注意力在选中 token 上的概率取平均，`exp(q·k·scale - lse_h)`，detach；
  - 学生：`softmax(S_idx * idx_scale)` 在同一组 token 上；`idx_scale` 默认 `1/sqrt(128)`（论文式 9），做成 Config 字段，因为 HF 没有训练路径；
  - 对所有 query 和 GQA 组取平均；
  - 梯度只到 indexer 的 4 个参数，单测要验证这一点；
  - 系数 λ 论文没给，做成 Config 字段，默认值要写明是我们定的；
  - 按 query 块分段计算。
- **为什么 KL 必须进第一期**：indexer 的参数只能从 KL 拿到梯度。没有 KL 的话它们永远没有梯度，DCP 加载 optimizer state 会出问题（#4025 里 shuhuayu 08-20 指出过 K3 第 0 层参数的同一问题）。
- **Warmup**（论文的 Indexer Warmup）：给 MSA 加一个 dense 模式，主分支跑完整因果注意力，KL 在所有因果 token 上算；冻结非 indexer 参数用一个 `ModelConfigTransform`（参考 `FreezeMoERoutingTransform`，`config/transform/freeze_moe_routing.py:17-32`），作为单独的一个阶段跑完再接着训。titan 里还没有按 step 切换模式的机制。是否进第一期，见第 7 节。
- **样本打包**：HF 的稀疏层不支持（indexer 用绝对位置）。titan 要支持，就得按文档起点划块（`pos // 128`，pos 每个文档从 0 开始），key 只看同一文档；不支持就照 K3 的先例报错加 TODO。见第 7 节。
  - 【2026-10-24 订正】已经支持：MM collator 本来就把多个样本拼进一行，所以 MSA 按文档起点划块（`block_T = cumsum(positions % B == 0) - 1`），选块和 mask 只看同一文档；单元测试用 3 个文档、文档起点不在 tile 边界上。
- M3 的第 0 到 2 层是普通 `GQAttention`（varlen 或 flex 后端），没有 indexer；M3.1-Flash 每层都是 MSA（Decoder 的头数检查依赖 `first_full_attention`，全 MSA 时会被跳过，MSA 要自己检查，照 DSV4 `model.py:245-257`）。

## 4. 视觉塔

- 本地的 `MiniMaxM3VisionEncoder`，用 common 的 block 拼：
  - Linear patch embedding（HF 的 Conv3d 权重在 adapter 里 reshape）；
  - pre LayerNorm（eps 1e-5），没有 post LayerNorm，没有可学习的位置编码，GELU 用精确版；
  - 3D RoPE：每轴 13 个频率，旋转前 78 维、两两配对 (i, i+39)，theta 1e4。
- 注意力范围照 SGLang：每个图片或视频一个 varlen 段，视频超过 4 个时间组就切段（`vision_segment_max_frames=4`）。HF 是所有 patch 一起全连，所以和 HF 对齐时只用"每次一张图、不超过 4 个时间组"的输入。
- 投影：每个 patch 先过 `linear_1`（1280 到 6144）、GELU、`linear_2`（6144 到 6144）；再把 2x2 的 4 个 patch 拼成 24576，过 `merge_linear_1`、GELU、`merge_linear_2` 到 6144。都带 bias。
- 占位 token：图像 200025、视频 200026、图像开始 200029、图像结束 200030（HF 给视频也用图像的开始和结束 token）。titan 的 `MultiModalTokenizer` 要求 5 个 token（含 pad），实现时对照 M3 的 tokenizer 确认。

## 5. Checkpoint adapter

- 文本：`language_model.model.*` 和 `language_model.lm_head.weight`；dense 层的 `gate_proj`/`up_proj` 合成 `w13`；专家 `block_sparse_moe.experts.{e}.w1/w2/w3` 堆成 grouped；共享专家；`block_sparse_moe.gate.weight`；`e_score_correction_bias` 映射到 `expert_bias_E`；indexer 的 `self_attn.index_{q_proj,k_proj,q_norm,k_norm}.weight`。
- 视觉：`vision_tower.vision_model.*`，patch embedding 从 Conv3d reshape 成 Linear；投影 `multi_modal_projector.linear_{1,2}` 和 `patch_merge_mlp.linear_{1,2}`。
- checkpoint 里 router、bias 和 patch embedding 是 fp32，其余 bf16；没有 `mtp.*`。
- `_validate_hf_rope_config(CosSinRoPE.Config)`。

## 8. 风险

- 并集 BlockMask 可能接近 dense，影响性能，但结果是精确的；以后再接融合的 MSA 训练 kernel。
- KL 和选块的显存：按 query 块分段。
- MSA 在 CP 下的设计（index key 只有一个头，all-gather 便宜；选中的 KV 块要跨 rank 取）放到 CP 那个 PR。
- λ 不知道；M3 实际的负载均衡方式不知道（HF 只有 Mixtral 式 aux loss，titan 用 bias 更新）。
- bf16 下 `ClampedSwiGLU` 和 HF 的舍入不同，对齐用 KL 阈值，不追求逐位。
