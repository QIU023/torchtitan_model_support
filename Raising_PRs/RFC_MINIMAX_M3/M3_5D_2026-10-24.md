## 设计

- 哪些维度写了：FSDP2/HSDP、TP + SP、EP、PP 都走 titan 现成的 seam（声明式 ShardingConfig、`make_*_config(enable_sp=...)`、MoE 的 EP、标准 PP 切分）。
- 哪个没写：CP。titan 的 CP 是 `ContextParallelTransform(inner_attention_map=...)` 换 inner attention，`prepare_cp_metadata` 只会把一个静态 mask_mod 改写成 local-Q / global-KV 的 BlockMask；MSA 的 mask 由每层 forward 里的 index q/k 现算（依赖数据），要做 CP 得写一套新算法（all-gather index key、按 load balancer 的 permutation 算本地 query 的选块、本地 Q x 全局 KV 的块 mask、KL 用全局 K）。这属于用户说的"特殊处理"一类，不写；titan 自己的 DeepSeek V4 稀疏注意力也是 "Context Parallel is not yet supported"。模型 `__init__` 遇到 cp > 1 抛 `NotImplementedError`。
- TP 的做法：
  - index query 头（每个 KV 组一个）跟 KV 组一起按 TP 切（`replicated_input_colwise_sharding_config`，`local_head_split` 拆头）；共享的 index key 头 replicated。每个 rank 只对自己的组选块、建 mask、算 KL。
  - MSA 层在模块边界把 `x_TD` gather 一次（`msa_attention_sharding_config`：in_src 残差 layout，in_dst R），q/k/v 和 index 投影共用；所以 MSA 层的 `wqkv` 换成普通 `Linear`（`ColumnParallelLinear` 在 SP 下会无条件 `maybe_gather_tp_input`，再 gather 一次就成了 2T，bring-up 时就是这样报错的）。Qwen3.5 的 attention 也是边界 gather 加普通 Linear。
  - `MSAIndexerLoss` 新增 `num_groups`（全局 KV 组数），每个 rank 用它归一化本地组的 KL，本地组数乘 TP 不等于它就报错（参照 DSV4 `SparseIndexerLoss` 的 `num_heads`）。日志值：`raw + (all_reduce(raw.detach()) - raw.detach())`，数值是 TP 全局和，梯度只走本地项（collective 在 detach 的标量上，和 DSV4 对 teacher 做 all-reduce 一样不进 autograd）。titan 的 `collect_aux_loss_metrics` 只按一个 mesh 名（加 pp）求和，没有 dp x cp x tp 的名字，所以在模型里做。
  - 第 0 层在 TP 复制的多模态 embedding 之后恢复残差 layout（P4 的 `transformer_block_sharding_config(after_vision_scatter=layer_id == 0)`），视觉 projector 结尾用 P5 的 `vision_projector_sharding_config`（I -> R，和文本 embedding 的 R 能相加）。
  - 视觉 3D RoPE 的角度在 typechecking 下标成 dp V、tp/cp I（从各 rank 自己的 grid 算出来）；只在最终角度上 mutate 一次（positions 是 I 但乘上 arange 来的 inv_freq（R）又会变回 R）。
- debug flavor：KV 头 4（和真实 M3 的 4 组一致，tp4 能切），8 层（pp8 放得下），5D 分支视觉塔 8 头、宽 128（tp4 时每 rank 2 头；1 头时 common `VisionAttention` 的 `reshape(T, -1)` 在 typechecking 下报歧义，不开 typechecking 时计算本身没问题）。

### 第 1 步差距的定位（10-24 晚订正；探针在 kit 的 `step1_probe.py`，运行目录 `step1/`，都在同一个 seed、同一个热 cache 上）

- **PP（上一版的结论是错的，已订正）：**
  - 上一版写 "norm、routed experts、router、lm_head 逐位，和 DSV3 同一模式"。实际 M3 pp2 对单卡 74 / 159 逐位，其中 43 个是纯文本下梯度为 0 的视觉塔参数；decoder 只有第 6、7 层是那样，第 0 到 5 层的 norm、experts、router 和 embedding 都有差（最大 3.7e-4）。DSV3 没有这个现象。
  - `M3_HOOK_BWD=4,5,6,7`：在 pp2 的 stage 1 和单卡的同一层上，每个 micro-batch 记 21 个模块边界的 forward 值和梯度（PP 多一次 stage 初始化的 forward / backward，输入全 0，对齐时跳过）。forward 全部逐位；第 7 层 flex attention 的 dQ 先不同，每个 micro-batch 0 到 3 行（共 512 行），dK、dV、dO 逐位；往前一层层放大。
  - 原因（`TORCH_LOGS=recompiles`）：单卡上 `flex_attention` 先给视觉塔编译（key 8 个头），MSA 再调时是 4 个 KV 头，触发重编译（"tensor 'key' size mismatch at index 1. expected 8, actual 4"），dynamo 的 automatic dynamic shapes 把头数标成动态维；pp2 的 stage 1 没有视觉塔，只编译一次、静态形状。两个 backward kernel 的 dQ 在少数几行上舍入不同。
  - 验证（`M3_STATIC_SHAPES=1`，即 `torch._dynamo.config.automatic_dynamic_shapes = False`，两边都设）：stage 1 的 672 条记录 0 条不同；第 1 步 decoder 参数梯度 70 / 116 逐位，不逐位的正好是 46 个 dense 投影权重（attention `wqkv` / `wo`、indexer `wq` / `wk`、shared experts、第 0 层 dense FFN），最大 7.7e-4。
  - 这 46 个是跨 8 个 micro-batch 累加的 bf16 梯度：单卡开 `fsdp_defer_gradient_reduction`（静态形状）动的也正好是这 46 个（最多 8.3e-4），pp2 和它之间还差 2.4e-4，所以 PP 的累加和两种单卡都不同。未改动的 DSV3 debug（varlen 注意力，没有视觉塔）pp2 对单卡也正好是全部 dense 投影不逐位（36 / 72），这是 titan PP 的累加，不是 M3 的代码，没有再往下拆。
  - 顺带的发现（不进正文）：同一个 rank 上视觉塔和 MSA 都调 `FlexInnerAttention.compiled_flex_attn` 的时候（单卡、PP 的第一个 stage、所有非 PP 格子），MSA 跑的是动态头数的那份 kernel。K3、Qwen3.5 这类视觉塔和 decoder 都走 flex 的模型应该也一样；性能影响没测。
- **EP（ep2 x fsdp2 对 fsdp2，没变）：** 0 到 6 层 forward 逐位；第 7 层 attention、router（分数 / id / map）、shared experts 逐位，routed experts 不逐位；专家 0 到 4、6、7 的输出逐位，只有专家 5 上 rank 0 的 10 个 token 不同。原因：`torch._grouped_mm`（bf16，sm86，torch 2.16.0.dev20261023）对同一行，在 10 行的组（无 EP）和 28 行的组（EP：10 + 18）里给出不同结果；用真实的分组布局单独复现（w13 形状 652 / 2560 个元素不同，w2 形状逐位）；另测 10 行组对 11 / 16 / 32 / 64 行组逐位、对 24 行组不逐位。EP 两次运行之间逐位相同。复现脚本 `grouped_mm_*.py` 已从 scratchpad 拷进 kit。
- **TP（tp2 x ep2、tp4 x ep4 对单卡）：**
  - 第 0 层 q / k / v 和 inner attention 输出（各 rank 自己的头）逐位，attention 输出不逐位，第一个差异是 row-parallel `wo`（K 维切开的部分和；block 输出相对差 8e-4）。
  - 离散决策跟着翻转（8 个 micro-batch 合计，rank 0 本地的 token 和组）：MSA（token, KV 组）选块不同 tp2 2.0%、tp4 2.3%（单次调用 0.5% 到 5.1%）；MoE top-k 专家集合不同的 token tp2 0.44%、tp4 0.39%（`M3_HOOK_SELECT_ALL`、`M3_HOOK_ROUTE_ALL`）。
  - 第 1 步梯度各参数组最大相对 L2：
    - 不强制：tp2 2.84e-2、tp4 3.64e-2（都是 router gate）。
    - 只强制单卡的选块（`M3_FORCE_SELECT`）：tp2 2.19e-2，attention 的 q / k norm 从 2e-2 降到 6e-3。
    - 选块和路由都强制（再加 `M3_FORCE_ROUTE`）：tp2 6.27e-3、tp4 5.64e-3。剩下的就是 TP 的规约顺序。
    - 对照：DSV3 tp2 x ep2 不强制 1.69e-2。上一版说 "M3 多出来的是选块翻转"，强制实验证实了一部分；只强制选块后还比 DSV3 高，是 M3 自己的路由翻转，强制路由后降到 6e-3。
  - indexer 梯度范数和单卡的比：tp2 wq 0.99988 / wk 1.00007，tp4 0.99977 / 0.99993（KL 的全局组数归一化正确；用本地组数归一化的话会差 2 倍、4 倍）。
- **组合格子：** ep2 / ep4 x fsdp2 x tp2 x pp2 的 rank 0 在第 0 到 3 层的 block 输出（本地 SP 那一半 token）对 fsdp2 的相对差是 8e-4、1e-3、3e-3、4e-3，和 tp2 x ep2 对单卡完全一样，所以组合格子的 forward 差异来自 TP。
