# MiniMax M3 调研记录（2026-10-24）

为 torchtitan 引入 MiniMax M3 和开 RFC 做的调研。每条事实注明来源；"原文"表示逐字核对过（论文 HTML 用 curl 下载、本地抽成文本后 grep，config 用 curl 读原始 JSON），"摘要"表示只经过 WebFetch 的摘要，写进 RFC 前还要对原文。

## 1. 技术报告是哪篇

- M3 的 GitHub README 写 "Read the technical report: arXiv:2606.13392"；M3.1-Flash 的 HF 模型卡也挂同一个 arXiv 徽章。
- arXiv 2606.13392 的标题是 **MiniMax Sparse Attention**（v1 2026-06-11，v2 06-12，17 位作者，30 页）。它是 MSA 机制论文，不是 M3 的完整模型报告：
  - 实验模型是一个 109B 的原生多模态 MoE（见第 3 节），论文里没有 M3 本身的配置；
  - 摘要只有一句 "A production-grade natively multimodal model powered by MSA has been publicly released at: https://huggingface.co/MiniMaxAI/MiniMax-M3."（原文）；
  - 没有任何分布式训练内容（CP、PP、EP、训练框架都没写）。
- 没有找到单独的 M3 或 M3.1 技术报告（10-24 搜索）。
- 另一篇 MiniMax 报告 arXiv 2605.26494 "The MiniMax-M2 Series: Mini Activations Unleashing Max Real-World Intelligence"（v1 05-26，v2 07-30）讲 M2 到 M2.7（M2 是 229.9B 总参、9.8B 激活）和 Forge RL 系统；titan 的 `torchtitan/rl/controller/WINDOWED_FIFO.md` 引用的就是它的 §6.2.4。它不涉及 M3。

## 2. MSA 机制（论文原文）

- 两个分支（§3）："a lightweight Index Branch selects a small set of key blocks from the causal context, and the Main Branch computes softmax attention over the tokens in those blocks. The Index Branch adds only two projection matrices to standard GQA, operates at block granularity, and makes selections independently for each GQA group."
- Index 分支（§3.1，式 5 到 7）：
  - 每个 GQA 组一个 index query 头，所有组共用一个 index key 头：`Q_idx = X W_q^idx` 形状 `(N, H_kv, d_idx)`，`K_idx = X W_k^idx` 形状 `(N, 1, d_idx)`；
  - token 级打分 `S = Q_idx K_idx^T / sqrt(d_idx)`，再在每个块内取 max（只取 `j <= i` 的 token），没有可见 token 的块记 `-inf`；
  - 每个 query、每个组选 top-k 块；"We always include the local block containing position i"，选出的块集合由组内所有 query 头共享。
- Main 分支（式 8）：对选中块里因果可见的 token 做标准 scaled dot-product attention，用本组的 KV 头。每个 query 的注意力开销从 `O(N)` 降到 `O(k B_k)`。
- 训练（§3.2）：
  - KL loss（式 9、10）：在选中块诱导出的 token 集合上，index 分布 `P_idx` 去拟合老师 `P`；老师是组内各 query 头的主分支 softmax 在概率层面取平均，并且 stop-grad；`L_KL` 对所有 query 位置和 GQA 组取平均。
  - Gradient Detach（式 11）：`Q_idx = stopgrad(X) W_q^idx`，`K_idx = stopgrad(X) W_k^idx`，所以 "L_KL updates only W_q^idx and W_k^idx"。
  - Indexer Warmup："During the first few iterations, the model runs full attention in both branches and trains the newly added index projections with L_KL. After warmup, the model switches to sparse attention"；从全注意力权重稀疏化时用同样的流程。
  - Local Block：训练和推理都强制选中本地块，占一个名额。
  - 总 loss（Algorithm 1）：`L = L_LM + λ Σ_layers L_KL`，由训练循环组装。**λ 的数值全文没有给出。**
- 最终方案（附录 B.2、B.3、C.3）：
  - 早期试过给 index 分支加 value 头、把 `W_o^idx O_idx` 加到层输出；有了 warmup 之后不再需要，"The final recipe, therefore, keeps the KL supervision but removes the Index Branch value head and its additive output path."（原文）。发布的 config 里每个稀疏层 `sparse_disable_index_value=1`，对应这一点。
  - 不做 detach 时 KL 梯度经过 index 投影回到主干：KL 系数大时几百步内出现梯度范数尖峰和 LM loss 发散；系数稳定时短上下文基准也会慢慢退化（自蒸馏效应）。detach 之后两个问题都消失。
- Kernel（§4）：exp-free top-k 选择、KV-outer 的稀疏注意力、稀疏 KL loss 的 LSE 融合（主前向时直接写出 LSE，跳过 KL 的前向）、动态负载均衡。

## 3. 论文里的实验模型和训练预算（§5.1，原文）

- 41 层 MoE，约 109B 总参、6B 激活；前 3 层 dense，后 38 层 MoE；词表 200K，hidden 3072。
- 注意力：MSA，64 个 query 头、4 个 KV 头，head dim 128，RoPE 维度 64。
- MoE：128 个路由专家、1 个共享专家、top-4。
- 稀疏训练和评测都用块大小 `B_k = 128`、每个 query 每个组保留 `k = 16` 块（共 2048 个 token）。
- 总预算 3T token：
  - MSA-PT 从头训，先 40B token 的 indexer warmup，之后一直稀疏训练；
  - MSA-CPT 从训了 2.6T token 的 GQA 全注意力权重出发，把注意力换成 MSA 再训 400B（前 40B 是 warmup）。
- 训练过程（§5.2）：MSA-PT 和全注意力的 LM loss 曲线在 3T token 上几乎重合，梯度范数也在同一范围；CPT 的 warmup 很快把 KL loss 降下来，切到稀疏之后 KL 保持在低位。
- 效率（摘要）：1M 上下文时每 token 注意力计算量降为 1/28.4；配合 kernel 在 H800 上 prefill 快 14.2 倍、decode 快 7.6 倍（相对 GQA）。

## 4. 发布的模型（config.json 原文，curl 读取）

M3（`MiniMaxAI/MiniMax-M3`，HF 仓库 2026-06-02 创建；另有 `MiniMax-M3-MXFP8`）：

| 部分 | 配置 |
|---|---|
| 总体 | README："~428B parameters and ~23B activated parameters"，1M 上下文，"mixed-modality training from the very first step" |
| 文本主干 | 60 层，hidden 6144，词表 200064，`max_position_embeddings` 1048576，embedding 与 lm_head 不共享 |
| 注意力 | 64 个 Q 头、4 个 KV 头，`head_dim` 128；`use_qk_norm`，`qk_norm_type=per_head`；部分 RoPE `rotary_dim=64`，`rope_theta=5e6`；`attention_output_gate=False` |
| Norm | `use_gemma_norm=True`（`x * (1 + w)`），`rms_norm_eps=1e-6` |
| 层的分布 | `moe_layer_freq` 和 `sparse_attention_freq` 都是第 0 到 2 层为 0、第 3 到 59 层为 1：前三层 dense FFN 加全注意力，其余 MoE 加 MSA |
| MSA | `sparse_index_dim=128`，`sparse_num_index_heads=4`，`sparse_topk_blocks=16`，`sparse_block_size=128`，`sparse_score_type=max`，`sparse_init_block=0`，`sparse_local_block=1`，稀疏层 `sparse_disable_index_value=1` |
| FFN | `hidden_act=swigluoai`（`swiglu_alpha=1.702`，`swiglu_limit=7.0`）；dense 层 `dense_intermediate_size=12288` |
| MoE | 128 个专家（`num_local_experts`）、top-4、1 个共享专家；专家和共享专家的 intermediate 都是 3072；`scoring_func=sigmoid`，`use_routing_bias=True`，`routed_scaling_factor=2.0` |
| MTP | config 写 `num_mtp_modules=7`、`num_nextn_predict_layers=1`；Megatron-Bridge 说发布的权重里没有 `mtp.*`（见第 5 节） |
| 视觉 | `clip_vision_model`：32 层，hidden 1280，16 头，MLP 5120，GELU，LayerNorm eps 1e-5，patch 14，`image_size=2016`，3D RoPE（theta 1e4）；`patch_merge`，空间 2、时间 2；`vision_segment_max_frames=4`；动态分辨率（`image_grid_pinpoints` 是 336 的倍数到 2016） |
| 投影和占位符 | GELU 投影带 bias，到 6144；`image_token_index=200025`，`video_token_index=200026`，`image_seq_length=576` |

M3.1-Flash（`MiniMaxAI/MiniMax-M3.1-Flash`，**2026-10-17** 创建）和 M3 的 config 差异（逐键比较）：

- 结构不变（README："M3.1-Flash retains M3's core mixture-of-experts architecture"），约 428B 总参、23B 激活；
- `sparse_attention_freq` 全部为 1："the first three full-attention layers are replaced with sparse attention"；
- 量化感知训练：`quantization_config` 是 MXFP8（`weight_block_size [1, 32]`）加 MoE 的 NVFP4（`nvfp4-pack-quantized`，`group_size 16`），部分 gate 层在 `ignored_layers` 里。HF 显示的 220490854016 是打包后的存储元素数。导入时要按打包格式解，不能当普通张量读（K3 的教训）；
- 没有 MTP；改为 DSpark 草稿头（仓库里的 `dspark/`）："DSpark replaces the earlier EAGLE-like MTP approach"；
- `rope_theta=1e7`，视觉 `image_size=672`；
- 技术报告链接仍是 arXiv 2606.13392。

## 5. 参考实现和生态现状

- **HF transformers（本地 5.20.2）有原生 `minimax_m3_vl`**：`transformers/models/minimax_m3_vl/modeling_minimax_m3_vl.py`（1578 行），含 `MiniMaxM3VLIndexer`（docstring 称 "Lightning Indexer"，每个 indexer 头独立选块，`index_n_heads == num_key_value_heads`）、`build_block_mask`、稀疏 KV cache。只有 MoE 的辅助负载均衡 loss，**没有 indexer 的 KL loss**。这是做数值对齐的参考。细节规格见 `PLAN_2026-10-24.md`。
- **Megatron-Bridge 从 07-14 起支持 M3**（`src/megatron/bridge/models/minimax_m3/`）：
  - 07-14 #4652（语言模型 bridge 和 recipe），07-23 #5002（纯文本数值验证），07-24 #5058（VLM 导入导出），08-10 #5448（EP 用 HybridEP）；
  - "Known limitations"（原文）："The lightning-indexer block-sparse attention branch (`self_attn.index_{q,k}_{proj,norm}`) is stored as frozen model state but is not executed; Megatron runs full causal attention on every layer." 序列不超过 2048 token 时数学上等价，更长时只是近似；
  - "MTP (Multi-Token Prediction) modules are not mapped. The released checkpoint advertises `num_nextn_predict_layers` in its config but ships no `mtp.*` weights"；
  - 负载均衡用 MCore 的 aux loss（`moe_router_load_balancing_type="aux_loss"`）。
  - 注意：Megatron 的 indexer 参数名里有 `index_{q,k}_norm`，论文式 5 没写 index 分支的 norm，以 HF 实现为准。
- **MSA kernel 仓库** `MiniMax-AI/MSA`（摘要）：MIT 协议；只支持 SM100（`fmha_sm100`）；"Full sparse attention (forward + paged FP8 decode, BF16 / FP8 / NVFP4 / FP4)"；CuTe-DSL 加 CUDA JIT；没写反向，也没有 PyTorch 参考实现。
- **推理侧**：SGLang 和 vLLM 都支持 M3 和 M3.1-Flash（README 和 cookbook）。
- **attn-gym 0.0.17**（本机已装）：`attn_gym.sparse.gather_attn` 有 reference、Triton、CuTe 三种实现，CuTe 只支持 SM100/SM103；另有 `attn_gym.sparse.indexer`。
- **所以，开源训练栈里还没有人真正训练 MSA**（稀疏前向和反向，加上 indexer 的 KL loss）。

## 6. torchtitan 上游现状（10-24）

- GitHub 上 pytorch/torchtitan 没有任何 MiniMax、M3 或 MSA 的 issue 和 PR（搜 "minimax" 只有 RL 的引用和我们的 #5595；搜 "MSA" 为 0）。
- 可复用的部件（main `3ed5aa97`）：
  - DSV4 的稀疏注意力：`torchtitan/models/deepseek_v4/attention.py` 用 attn-gym 的 `gather_attn`；`deepseek_v4/compressor.py` 有 `Indexer` 和 `SparseIndexerLoss(AuxLoss)`，目前在模型目录里；
  - `models/common/activation.py` 有带 clamp 的 SwiGLU（`swiglu_alpha=1.702`、`swiglu_limit=7.0`，与 M3 相同）；
  - `models/common/moe/moe.py` 的 router 支持 `score_func`（sigmoid）、`expert_bias_E`、`route_scale`。
- 同类 PR 的样子：GLM-5 #5578（10-21 开，还没合入，loveofguoke）+3865 行、19 个文件，DSA 写在模型目录 `glm5/dsa.py`，带 `mtp.py`、对 HF 的数值测试脚本、CPU 单测、recipe，并在 `tests/integration_tests/models.py` 加一条。
- K3 的时间线（教训）：K3 是 07-27 发布的，#4025 "[kimi k3] add eager reference model with FSDP2"（JavaZeroo）在 **07-30** 就开了，08-24 合入，+2752 行、20 个文件；之后我们本地的 5D 分支都只能 rebase 到它上面。
- M3 已经发布 4 个多月，titan 仍然没人做；M3.1-Flash 10-17 刚发布。窗口还在，但随时可能有人开 PR。

## 7. 待核对和未决

- λ（KL 系数）的数值：论文没给。要么从 HF/SGLang 侧找不到（它们不训练），只能做成配置项。
- index 分支的 QK norm：以 HF 实现为准（Megatron 的参数名里有）。
- MSA 在 CP 下怎么做：论文没写分布式训练。index key 只有一个头，CP 时需要对它和选中块的 KV 做聚合，设计放到后续 PR。
- 视觉塔：CLIP 式加 3D RoPE，和 titan 现有的视觉塔（MoonViT、Qwen3.5、Muse）哪个最接近，见 `PLAN_2026-10-24.md`。
- 视觉塔的注意力范围（已查清）：HF 把一次调用里所有 patch 拼成一条序列、`attention_mask=None`，图片之间互相注意（Megatron-Bridge 跟 HF 一致，并把"分段的多图和视频"列为限制）；SGLang 的 `minimax_vl_common.py` 则是每个图片或视频一个 varlen 段（`_compute_cu_seq_len`），视频超过 `vision_segment_max_frames=4` 个时间组时切成每段至多 4 组（`_apply_max_frames_limit`）。titan 按 SGLang 的分段做，和 HF 对齐时只用"每次一张图、不超过 4 个时间组"的输入。
- MTP：M3 的权重里没有，M3.1-Flash 换成了 DSpark，第一期不做。
